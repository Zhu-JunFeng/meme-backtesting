# 外部信号触发后入场

`POST /api/backtests` 的 `dataset.entrySignals` 可携带 `{chain, ca, signalTime}` 数组。
`signalTime` 是 UTC 毫秒时间戳。同一链/CA 的多个信号取最早值，应用于其所有选定交易池。
启用时必须覆盖全部选定 CA；缺失、不合法或超出数据集的信号直接拒绝，不默认放行。
省略该字段维持既有行为。完整限制保存到任务配置/数据集快照，重新回测也保留。

用户确认允许使用发现项目时已经存在的历史 K 线。信号前逐根更新指标和已确认 Pivot，
但不买入、不加仓、不占用现金/持仓，也不消耗一次性入场机会或信号边沿。
首次允许执行时，按当时条件重新判断；不复用信号前本应成交的订单。
仅允许 `candle.time > signalTime`：K 线时间是开盘时间，信号所在桶和时间恰好相等的桶均禁止入场。
信号在数据结束后时保留零交易项目。退出、费用、资金竞争和现有缺口处理规则不变。

每次买入/加仓事件的 `reason_json.monitoringSignal` 保存原信号时间及门槛规则，方便逐笔审计。
这是重新逐 K 线撮合，不是对已有交易事后删单。新的 `portfolio-5` / 检查点 v4 支持该规则。
旧 portfolio-4 检查点只在没有新信号限制的配置下兼容恢复；旧 portfolio-3 还要求未开启锁盈。
运行时依旧校验完整配置校验和，不允许更改历史检查点配置后继续。

只读解析脚本 `scripts/signal-entry-manifest.py` 使用项目导入 Skill 的 XLSX 读取器，
核对毫秒时间戳与北京时间列，输出去重表、来源行号及文件 SHA256。
不读取最高收益/最高市值等事后字段来决定入场或选币，不导入行情、不改工作簿。
