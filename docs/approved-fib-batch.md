# 固定批次 fib-grid-20260920-v1

用户确认的 864 组有限方案 × SOL/ROBIN，加两条链 v4 对照，共 1730 个任务。
候选清单唯一来源：`apps/api/src/batch-grid.ts`。不会改写原策略版本或历史任务。

部署后通过 GitHub Actions 的 **Approved Fib batch** 手动选择：

- `preview`：校验所有策略及两个来源输入，导出完整候选清单、校验和及行数。
- `pilot`：提交 8 个先导任务（两条链对照 + A–F 各一例），使用清单内固定 ID。
- `status`：只读查看批次进度、失败原因。
- `submit`：要求先导全部完成，两个对照的报告、交易和事件与来源一致，且数据库磁盘足够；然后提交其余任务。单次中断可再次执行，不重复创建。
- `export`：JSON 汇总，SOL、ROBIN 分开按净盈亏排序；内部 CLI 可加 `--csv` 导出 CSV。

内部 CLI：`BACKTEST_CLI=1 node apps/api/dist/batch-cli.js <command>`。
写操作必须 `--yes`、生产队列以及数据库文件系统实际可用 `BATCH_FREE_BYTES`。
估算保留 5 GiB，加先导同链最大结果体积 × 剩余数量 × 3（索引、膨胀和策略差异余量）。不够则暂停，绝不删除历史数据。

输入只引用原始完成任务；共享源的配置、输入分块和清单受数据库保护，检查点绑定源 ID。普通任务及旧检查点仍使用自身输入；重新回测操作仍创建新任务重新冻结，不继承共享引用。
批次任务每个独立使用 100000 初始资金，池内共享资金。Worker 并发保持 1。失败任务保留记录，由现有停止/重试操作处理，不自动从头重跑。
结果为同样本参数筛选，不是样本外或未来收益验证。
