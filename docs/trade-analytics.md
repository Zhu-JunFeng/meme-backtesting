# 交易统计与多档动态锁盈

- `GET /api/backtests/:id/statistics?includeEndOfBacktest=false` 返回过滤后统计、累计已实现余额曲线、排除数量/净盈亏、信号数量和卖出原因，以及原报告与原权益曲线。默认 `true` 保持原账户指标。曲线相同退出时刻合并净盈亏，不回放资金分配，不包含浮盈。
- `/cas`、`/ca`、`/trades`、`/signals`、`/locate` 接收相同开关。关闭时排除结束平仓整笔订单的买入、加仓、卖出及 Fib；无法确认订单归属的交易事件也隐藏并提示数量，独立风险事件不作为卖出。原始历史报告和订单不更新，开启后恢复原编号。
- 上述查询支持 `signalTypes=take_profit,profit_lock`：先按任一类型匹配整笔交易，再分页或截取图表区间。首次买入/加仓按关联事件匹配，卖出按退出原因匹配；风险事件不作为交易筛选类型。CA/池只保留匹配订单并汇总其已实现盈亏，未筛选时仍保留零交易 CA。`statistics` 不应用信号类型筛选，顶部统计及标签计数只跟随结束平仓开关。
- 前端统一使用 `format.ts` 中的 `numberDisplay` 配置：普通数值两位，计数整数，小币价/极小数量保留有效位，Fib 参数和原始核验数据不舍入。`ResultValue` 统一展示盈亏正绿负红、零值中性，回撤按负向语义红色显示，普通市值/数量/费用保持中性色。
- 交易收益率分母为累计买入金额 + 买入手续费/滑点/税。新记录明确持久化分项；历史仅通过唯一匹配的首次买入及全部加仓事件和任务成本快照还原。缺失或歧义显示不可用。
- `trade_no` 在任务/链/CA/池内唯一，事件通过同范围 `trade_no` 和 `event_order` 关联，支持未平仓及跨结果批次。历史编号在完整池交易集合上计算，不受查询分页/时间/过滤影响。同一入场时间无法区分的旧交易不编造编号。

## 锁盈配置

```json
{"profitLock":{"enabled":true,"tiers":[{"activationPercent":50,"floorPercent":20},{"activationPercent":100,"floorPercent":60}]}}
```

位于 `exitConfig`。收盘按当时加权成本确认激活，下一根才执行；启用后绝对锁盈价不下调。加仓不撤销已激活档位，尚未激活档位按最新均价计算。固定盈亏比的目标仍由原始止损计算，不使用抬升后的锁盈线重算。止损优先于失效、止盈、超时、结束平仓；跳空穿线按开盘值退出。毛保底比例不保证扣费后净利润。

## 发布与兼容

先应用 `005_trade_analytics.sql`（只加字段/索引/注释），再发布 API、Worker 和前端。引擎 `portfolio-4`，检查点 3；检查点 2 / portfolio-3 仅在配置未启用锁盈时可迁移恢复，原现金、指标、仓位保持不变，持仓买入成本从原状态恢复。其他版本拒绝恢复。更新后的检查点不能用旧版 Worker 回滚消费。

验证命令：`pnpm -r build`；`TEST_DATABASE_URL=...test... pnpm -r test`。数据库测试必须使用独立测试库，runtime 集成套件创建所需表并迁移后 API 集成套件验证统计一致性。界面验证使用隔离本地服务，不自动重跑生产历史任务。
