# 可恢复回测运行协议

## 行为

- 新执行器：`portfolio-3`，检查点格式版本 2，运行协议 `checkpoint-1`。
- 本地默认队列前缀 `meme-local-v3`，生产 `meme-production-v3`。API 与 Worker 必须配置相同 `BACKTEST_QUEUE_PREFIX`。
- 任务阶段：冻结输入（进度 0–10%）→ 计算（10–95%）→ 保存结果 → 完成。
- 停止执行任务先进入 `stopping`，在完整时间批次后保存检查点，变为 `stopped`；重试保留相同配置和输入。重新回测新建任务、重新冻结输入，不覆盖旧结果。
- POST `/api/backtests/:id/stop`、`/retry`、`/rerun`；rerun body 为 `{requestId: UUID}`，客户端重试必须复用该标识。历史 `/cancel` 为安全停止兼容入口；旧运行协议任务需人工盘点，不能伪装成已安全停止。
- 任务列表/详情暴露 `phase`、`heartbeat_at`、`checkpoint_at`、`recovery_count` 和 `actions`。未完成任务的交易与权益是已提交的阶段结果，最终报告只在完成后发布。

## 数据与恢复边界

每池使用 PostgreSQL 游标的固定查询快照读取行情，按最多 256 根写入分块，池清单与分块原子提交。没有完成的池在中断时回滚；已经完成的池保留原数据。所有池冻结完成之后才计算，后续源表 UPSERT 不影响恢复和新任务图表。

引擎只保存有限历史窗口、增量 Pivot、EMA、RSI、成交量与 OBV 状态，虚拟平价缺口按需生成。保持旧引擎的 RSI 简单窗口公式，未切换为 Wilder RSI。阈值附近回退到有界窗口的参考计算，减小浮点累加误差对信号的影响。

检查点包含输入游标、现金、持仓、信号边沿、指标和统计；每 30 秒或累计 10000 条结果记录提交。结果批次和检查点在同一个事务内提交。执行器每 2 秒续租，租约 60 秒；写入事务校验递增代次并锁定任务行，旧执行器失去租约后不能写入。运行中无检查点前的异常只能从头计算，冻结完成的池仍可复用。

API/Worker 每 5 秒协调失效租约；连续 3 次失效后标记失败，成功检查点重置连续失败计数。业务校验或 SQL 错误直接标记失败，保留最后检查点供人工重试。检查点版本或配置校验和不匹配时明确失败，不静默重跑。

## 停机和发布

生产镜像直接启动编译后的 Node 程序，禁止 watch 开发模式。SIGTERM 停止领取任务、提交检查点并释放任务为 pending，新进程使用新的投递序号恢复。未完成的 BullMQ 执行不标记成功；数据库状态是业务任务的权威状态。发布使用 `docker stop --time 90`，不再直接 `docker rm -f`。

`deploy/release.sh` 在存在旧版 pending/running 任务时拒绝切换。首次发布前必须核对旧队列和本地旧 Worker，明确完成、取消或重新创建哪些旧任务；旧任务无检查点，不能承诺原地续跑。脚本未提供绕过安全检查的自动开关。数据库迁移失败或镜像构建失败会直接终止发布。

执行 migration 004 后部署 API、Worker、前端。迁移会保留全部历史任务与最终报告。输入快照、检查点和阶段结果增加磁盘占用，当前随任务保留并在删除任务时级联删除；没有自动清理历史数据。

## 图表

GET `/api/backtests/:id/locate?chain=...&ca=...&pairId=...&tradeId=...` 返回交易和实际 K 线范围。不传 tradeId 时选择第一笔交易，eventId 定位单事件。买卖点各取前后 100 根实际原始行情，先加载目标区间（每页最多 5000 根）再创建图表。未平仓定位买入附近；无交易展示池末尾。事件仍用原始价格/市值和数量，缺失行情不补造。

## 验证记录（2026-09-20，本地测试环境）

- 生产源只读复制：390 CA / 391 池，928657 根有效原始行情，按原规则计算 4927422 根。
- 复制耗时 139.05 秒（含跨公网传输）；新引擎计算与结果写库 24.10 秒；采样峰值 RSS 518.44 MiB。不能将本机性能当作 1.8 GiB 生产主机的性能，也不据此声称同机提速倍数。
- 固定输入新报告与原生产 portfolio-2 完成报告逐字段一致，仅 engineVersion 不同；339 笔交易，净盈亏 -6775.471622165837。
- 真实 Worker SIGTERM 演练：约 10.9% 保存检查点后退出，新 Worker 恢复完成，完整报告与不中断基线一致。
- SIGKILL 演练：在检查点提交后强制终止进程，测试库中模拟租约到期，再启动 Worker；恢复报告与基线一致。正常 SIGTERM 续跑后的 339 笔交易、678 个事件与原生产任务逐条一致（忽略行 ID 和任务 ID）。
- 数据库集成测试覆盖源数据变更、停止/重试幂等、停止与最终提交竞争、租约失效和代次隔离、重新回测幂等。独立测试数据库，不修改生产任务。
- 图表浏览器验证：打开 CA 的第一条行情请求落在第一笔交易附近，原始首次买入、加仓、止盈、止损标注均可见，控制台无错误。

## 重现

先准备独立 PostgreSQL 测试库（名称必须含 test），不要指向生产库：

```sh
pnpm build
TEST_DATABASE_URL=postgresql://127.0.0.1:55439/meme_runtime_test pnpm test
```

真实数据基准脚本仅允许写入本机测试库，生产源连接强制只读：

```sh
# SOURCE_DATABASE_URL、TEST_DATABASE_URL 从受保护环境配置读取，不写入仓库。
node packages/runtime/scripts/benchmark.mjs SOURCE_RUN_UUID
# 使用上一步输出的测试任务 ID，Redis 必须为独立本地实例。
BACKTEST_QUEUE_PREFIX=meme-grace-test node packages/runtime/scripts/rehearse-shutdown.mjs LOCAL_BASELINE_UUID
```

CI 提供 PostgreSQL 17 测试服务并执行集成测试。正式发布前仍需在预发布服务器按其 CPU、内存和磁盘条件复测 700 MiB 目标，并确认旧任务处理方案。
